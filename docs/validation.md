# Input validation rules

This document gathers in one place the input rules already written in the proto comments. It creates no new rules. This repo does not use validation annotations (protovalidate or similar) on proto fields, so **the rules are a contract, and each server enforces them.** Whether a server really checks these rules cannot be confirmed in this repo (needs checking, in each server repo).

A failed rule returns the status shape and `ErrorInfo.reason` in the [gRPC error contract](errors.md).

| Input | Rule | Source |
| --- | --- | --- |
| Resource id (except Object), project, region, zone | `[a-z]([a-z0-9-]{0,61}[a-z0-9])?`, length 1-63 | `vws/common/v1/resource.proto` `ResourceId` |
| Label key | `[a-z][a-z0-9_-]{0,62}` | the envelope comment in the same file |
| Label value | UTF-8, 0-63 bytes, no ASCII control characters | the same file |
| Annotation key and value (Instance, Volume, Vpc, Subnet) | Key 1-128 and value 0-256 characters of UTF-8 with no control characters, counted in Unicode characters, not bytes. At most 50 user entries. A key beginning with `aws:` is reserved: it does not count toward the 50, and a user create or update that sets or changes one is `INVALID_ARGUMENT / INVALID_SPEC`. Servers accept at least 64 KiB per resource. Stored and returned verbatim, not filterable, no generation change; an identical write is a no-op. EC2 accepts any character in a tag, so this rule is deliberately stricter on control characters; the envelope comment gives the reason. A malformed key or value is `INVALID_ARGUMENT / INVALID_SPEC` with the EC2 `InvalidParameterValue` sentence, for example `Value (<value>) for parameter tagValue is invalid.` | the envelope comment in `vws/common/v1/resource.proto` |
| Annotation write | `CreateTags` merges: a key in the request overwrites the value of the same key, a key repeated within one request keeps the last value, and keys the request does not name stay. The 50-entry limit applies to the merged user entries. UpdateMask path `annotations` replaces the user entries but keeps every existing server-set `aws:` key and its value, so a write that omits one leaves it in place; sending a stored `aws:` key with its stored value unchanged is accepted | the same file |
| Object key | 1-1024 bytes after decoding, not `.` or `..`, does not start or end with `/`, no `//`, no ASCII control characters. RFC 3986 percent-encoding in paths (`/` is `%2F`) | `vws/storage/v1/object.proto` `Object` |
| Bucket `namespace` | `BucketNamespace`. `UNSPECIFIED` means `GLOBAL`. `ACCOUNT_REGIONAL`: the bucket id must end with `-{account}-{region}-an`, where `{account}` is the caller's 12-digit account id and `{region}` is `spec.region`. Another account's or region's suffix, or no suffix, is `INVALID_ARGUMENT / INVALID_BUCKET_NAMESPACE`. `GLOBAL`: an id ending with `-an` is `INVALID_ARGUMENT / INVALID_BUCKET_NAMESPACE` (S3 reserves the suffix for the account regional namespace). The suffix counts toward the 63-character id limit. Immutable | `vws/storage/v1/bucket.proto` `BucketSpec` |
| Volume `type` | One of the EBS types `GP2`, `GP3`, `IO1`, `IO2`, `ST1`, `SC1`, `STANDARD` (EC2 `VolumeType`). `UNSPECIFIED` is invalid. `SSD` is deprecated: clients do not send it, and a stored `SSD` volume reads as `GP2` unless the admin maps it otherwise (vws-storage#123). Immutable | `vws/storage/v1/volume.proto` `VolumeType` |
| Volume `iops` and `throughput_mibps` | As in EC2 CreateVolume. GP3: `iops` 3000-80000 (0 uses 3000) and `throughput_mibps` 125-2000 (0 uses 125). IO1: `iops` 100-64000, required. IO2: `iops` 100-256000, required. Every other type, and `throughput_mibps` on every type but GP3: must be 0 | `vws/storage/v1/volume.proto` `VolumeSpec` |
| `ModifyCreateVolumePermission` caller and `name` | Only the owning project of `name`. A snapshot that does not exist, has a delete accepted, or belongs to another project (even one it is shared with) is `NOT_FOUND / RESOURCE_NOT_FOUND` (EC2 `InvalidSnapshot.NotFound`), so a grant never reveals or lets a grantee change a snapshot. Same for `GetCreateVolumePermission` | `vws/storage/v1/snapshot.proto` `ModifyCreateVolumePermissionRequest`, `GetCreateVolumePermissionRequest` |
| `ModifyCreateVolumePermission` `add`, `remove` | At least one entry across both, and at most 500 entries in total (EC2 limit of 500 modifications per call). Each `projects` entry is `projects/{project}` with a `ResourceId` project. The gateway maps EC2 `UserId` to the project and `Group` `all` to `all = true`; any other `Group` value is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidParameterValue`). An empty request, more than 500 entries, a malformed project, projects in both `add` and `remove` (EC2 does not add and remove account ids in one call), or `all` in both is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidParameterValue`) and nothing changes. A project change and an `all` change may share one call, as in the EC2 example that removes a UserId and adds Group `all`. The owning project in `add` or `remove` is a no-op. A well-formed project that does not exist is stored, so the call does not reveal which projects exist. Granting an entry already granted, or revoking one not granted, is a no-op. The change applies in one write | the same message |
| Instance `user_data` and `user_data_raw` | Each at most 32768 bytes. `user_data` is a proto3 string and must be valid UTF-8; `user_data_raw` carries any bytes, including non-UTF-8 EC2 UserData, and is passed to the guest unchanged. Both set is `INVALID_ARGUMENT / INVALID_SPEC` | `vws/compute/v1/instance.proto` `InstanceSpec` |
| Volume attachment `delete_on_termination` | Optional bool. Unset means true for the `boot = true` attachment and false for every other attachment. Any value is valid; servers do not reject it | `vws/compute/v1/instance.proto` `VolumeAttachment` |
| Volume attachment `attach_time` | Output only. Servers ignore client values in `VolumeAttachment.attach_time` and keep the stored value; it is never a validation error. Set once when the entry first appears in `spec.volumes`, then copied once to `ObservedVolumeAttachment.attach_time` by the node | `vws/compute/v1/instance.proto` `VolumeAttachment`, `ObservedVolumeAttachment` |
| IAM name (`IamName`): user, group, role, MFA device and inline policy names | `[A-Za-z0-9+=,.@_-]`. Users, roles and MFA devices 1-64 characters. Groups, managed policies and inline policies 1-128 characters (AWS CreateGroup GroupName, CreatePolicy and Put{User,Group,Role}Policy PolicyName). Unique within a project, ignoring case. An exception to `ResourceId` for AWS compatibility | `vws/iam/v1/*.proto` |
| `new_user_name`, `new_group_name` | Optional `IamName`: users 1-64, groups 1-128 characters. Empty means no rename. When set, `update_mask` is empty (rename only) or names only `spec.path` and `labels`; any other path is `INVALID_ARGUMENT / INVALID_SPEC`. A name taken in the project, ignoring case, is `ALREADY_EXISTS / ALREADY_EXISTS` (AWS `EntityAlreadyExists`) and nothing changes. A missing user or group is `NOT_FOUND / RESOURCE_NOT_FOUND` (AWS `NoSuchEntity`), even with `allow_missing`. A stale etag is `ABORTED / ETAG_MISMATCH`. The operation response has the new resource name | `vws/iam/v1/user.proto` `UpdateUserRequest`, `vws/iam/v1/group.proto` `UpdateGroupRequest` |
| Access key id | `AKIA` (long-term) or `ASIA` (temporary) + 16 upper-case letters and digits | `vws/iam/v1/access_key.proto`, `auth.proto` |
| `expected_user_path` | AIP-122 user resource name `projects/{project}/users/{user}`. When set and different from the access key's parent user, `FAILED_PRECONDITION` and no state change | `vws/iam/v1/access_key.proto` `UpdateAccessKeyRequest`, `DeleteAccessKeyRequest` |
| `expected_user_arn` | IAM user ARN `arn:vws:iam::{project}:user{path}{user}`. When set and different from the parent user's current ARN, `FAILED_PRECONDITION` and no state change. Omitted means no check. The ARN contains the IAM path, so this catches a path move by `UpdateUser` | `vws/iam/v1/access_key.proto` `UpdateAccessKeyRequest`, `DeleteAccessKeyRequest`; `vws/iam/v1/user.proto` `SetLoginProfileRequest`, `DeleteLoginProfileRequest` |
| `user_etag` | Optional string, the target User's etag (for an access key, its parent User) as read by the caller. When set, the write commits only while the user is still at this etag. A mismatch, or a change of the user that lands before the commit, is `ABORTED` (AWS `ConcurrentModification`) and no state change. Omitted means no check. On the login profile requests, a user deleted and recreated under the same name never matches an etag read before the delete, and a successful write changes the etag, so a retry after a lost response reads the User again or is `ABORTED` | `vws/iam/v1/access_key.proto` `CreateAccessKeyRequest`, `DeleteAccessKeyRequest`; `vws/iam/v1/user.proto` `SetLoginProfileRequest`, `DeleteLoginProfileRequest` |
| Login profile `mode` | `LoginProfileWriteMode`. `UNSPECIFIED` or `UPSERT` creates or replaces the hash. `CREATE_ONLY` on an existing profile is `ALREADY_EXISTS / ALREADY_EXISTS` (AWS `EntityAlreadyExists`). `MUST_EXIST` on a missing profile is `NOT_FOUND / RESOURCE_NOT_FOUND` (AWS `NoSuchEntity`). Checked in the same store mutation as the hash write; nothing changes on error | `vws/iam/v1/user.proto` `SetLoginProfileRequest` |
| `ResyncMfaDevice` `user_name` | 1-128 characters of `[\w+=,.@-]`. `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`) | `vws/iam/v1/mfa_device.proto` `ResyncMfaDeviceRequest` |
| `ResyncMfaDevice` `serial_number` | 9-256 characters of `[\w+=/:,.@-]`. `INVALID_ARGUMENT / INVALID_SPEC`. A serial that is not a device enabled for the user is `NOT_FOUND / RESOURCE_NOT_FOUND` | `vws/iam/v1/mfa_device.proto` `ResyncMfaDeviceRequest` |
| `ResyncMfaDevice` `authentication_code_1`, `authentication_code_2` | Exactly six digits each. `INVALID_ARGUMENT / INVALID_SPEC` otherwise. A wrong, out-of-window or already used pair is `UNAUTHENTICATED / INVALID_CREDENTIALS` | `vws/iam/v1/mfa_device.proto` `ResyncMfaDeviceRequest` |
| `PutRolePermissionsBoundary` `permissions_boundary` | 20-2048 characters, else `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`). Not of the form `arn:vws:iam::{project}:policy/...` is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidInput`). Not a managed policy of the role's project, path included, is `NOT_FOUND / RESOURCE_NOT_FOUND` (`NoSuchEntity`). The role id in `name` is IamName, 1-64 characters | `vws/iam/v1/role.proto` `PutRolePermissionsBoundaryRequest` |
| `DecodeAuthorizationMessage` `encoded_message` | 1-10240 characters, else `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`). Not a message vws-iam issued for the caller's project, tampered, expired or with an unknown key is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidAuthorizationMessageException`) | `vws/iam/v1/auth.proto` `DecodeAuthorizationMessageRequest` |
| `DecodeAuthorizationMessage` `source_ip` | Set by the gateway from the observed connection, never from client input. Empty means unknown (`aws:SourceIp` absent) | the same message |
| `GetAccessKeyInfo` `access_key_id` | 16-128 characters of `[\w]`, else `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`). A key that does not exist is `NOT_FOUND / RESOURCE_NOT_FOUND` (`InvalidClientTokenId`) | `vws/iam/v1/auth.proto` `GetAccessKeyInfoRequest` |
| `GetAccessKeyInfo` `source_ip` | Set by the gateway from the observed connection, never from client input. Empty means unknown (`aws:SourceIp` absent) | the same message |
| `GetFederationToken` `name` | 2-32 characters of `[\w+=,.@-]`, else `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`) | `vws/iam/v1/auth.proto` `GetFederationTokenRequest` |
| `GetFederationToken` `duration_seconds` | 900-129600, zero means 43200, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). A root caller's session is capped at 3600 | the same message |
| `GetFederationToken` `policy` | Empty, or 1-2048 characters of `[\u0009\u000A\u000D\u0020-\u00FF]`, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). Not a parseable policy is `INVALID_ARGUMENT / INVALID_SPEC` (`MalformedPolicyDocument`). Never logged | the same message |
| `GetFederationToken` `policy_arns` | At most 10, each 20-2048 characters, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). Not a managed policy of the caller's project is `INVALID_ARGUMENT / INVALID_SPEC` (`MalformedPolicyDocument`). The plaintext of `policy` plus `policy_arns` over 2048 characters in total is `INVALID_ARGUMENT / INVALID_SPEC` (`PackedPolicyTooLarge`) | the same message |
| `AssumeRoleWithSAML` `role_arn`, `principal_arn` | 20-2048 characters each, else `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`). An unknown role, or a pair the assertion's Role attribute does not grant, is `PERMISSION_DENIED / ACCESS_DENIED` (`AccessDenied`). An unknown SAML provider is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidIdentityToken`) | `vws/iam/v1/auth.proto` `AssumeRoleWithSAMLRequest` |
| `AssumeRoleWithSAML` `saml_assertion` | 4-100000 characters, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). Not base64 or XML, unsigned, signed by a certificate the provider does not list, more than one assertion, another audience, recipient, destination or issuer, or no Role or RoleSessionName attribute is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidIdentityToken`). Expired is `UNAUTHENTICATED / TOKEN_EXPIRED` (`ExpiredToken`). A status other than Success is `PERMISSION_DENIED / ACCESS_DENIED` (`IDPRejectedClaim`). A bearer credential, never logged | the same message |
| `AssumeRoleWithSAML` `duration_seconds` | 900-43200 and not above the role's `max_session_duration_seconds`, zero means 3600, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`) | the same message |
| `AssumeRoleWithSAML` `policy`, `policy_arns` | `policy` is empty or 1-2048 characters of `[\u0009\u000A\u000D\u0020-\u00FF]`; `policy_arns` has at most 10 entries of 20-2048 characters. Otherwise `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). A policy that does not parse, or an entry that is not a managed policy of the role's project, is `INVALID_ARGUMENT / INVALID_SPEC` (`MalformedPolicyDocument`). When each passes its own limit, the plaintext of `policy` plus `policy_arns` over 2048 characters in total is `INVALID_ARGUMENT / INVALID_SPEC` (`PackedPolicyTooLarge`). Never logged | the same message |
| `AssumeRoleWithSAML` `source_ip` | Set by the gateway from the observed connection, never from client input. Empty means unknown (`aws:SourceIp` absent) | the same message |
| `AssumeRoleWithWebIdentity` `role_arn`, `role_session_name` | `role_arn` 20-2048 characters; `role_session_name` 2-64 characters of `[\w+=,.@-]`. Otherwise `INVALID_ARGUMENT / INVALID_SPEC` (AWS `ValidationError`). An unknown role is `PERMISSION_DENIED / ACCESS_DENIED` (`AccessDenied`) | `vws/iam/v1/auth.proto` `AssumeRoleWithWebIdentityRequest` |
| `AssumeRoleWithWebIdentity` `web_identity_token` | 4-20000 characters, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`). Not a compact JWS, an algorithm other than RS256, RS384, RS512, ES256, ES384 or ES512, a bad signature, an issuer with no OIDC provider in the project, no audience in the provider's client id list, a non-integer `exp`, `nbf` or `iat`, or a future `nbf` or `iat` is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidIdentityToken`). Expired is `UNAUTHENTICATED / TOKEN_EXPIRED` (`ExpiredToken`). A JWKS that cannot be fetched is `UNAVAILABLE / RECONCILIATION_FAILED`, `retryable=true` (`IDPCommunicationError`). A bearer credential, never logged | the same message |
| `AssumeRoleWithWebIdentity` `provider_id` | Empty. 4-2048 characters is `INVALID_ARGUMENT / INVALID_SPEC` (`InvalidIdentityToken`); another length is `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`) | the same message |
| `AssumeRoleWithWebIdentity` `duration_seconds` | 900-43200 and not above the role's `max_session_duration_seconds`, zero means 3600, else `INVALID_ARGUMENT / INVALID_SPEC` (`ValidationError`) | the same message |
| `AssumeRoleWithWebIdentity` `policy`, `policy_arns` | As for `AssumeRoleWithSAML`: `ValidationError`, then `MalformedPolicyDocument`, then `PackedPolicyTooLarge`. Never logged | the same message |
| `AssumeRoleWithWebIdentity` `source_ip` | Set by the gateway from the observed connection, never from client input. Empty means unknown (`aws:SourceIp` absent) | the same message |
| `Principal.session_context` | Opaque, sealed and set only by vws-iam (`Authenticate`), bound to the session's `arn`, `unique_id`, project and expiry; the gateway never builds it. A principal with type `PRINCIPAL_TYPE_FEDERATED_USER` or a federated-user ARN without one, or with one that does not open, has expired or is bound to another session, is `DENY_IMPLICIT` in `Authorize`. Never logged | `vws/iam/v1/auth.proto` `Principal` |
| IAM `path` | Starts and ends with `/`, 1-512 characters | the same files |
| Policy document | AWS JSON, `Version` `2012-10-17`. At most 6144 characters excluding whitespace. Unparseable, or a condition outside `docs/iam.md`, is `INVALID_ARGUMENT / INVALID_SPEC` | `policy.proto` |
| IAM tag key | 1-128 characters of `[\p{L}\p{Z}\p{N}_.:/=+\-@]`, not beginning with `aws:`. Case sensitive. At most 50 tags per policy or virtual MFA device. `INVALID_ARGUMENT / INVALID_SPEC` when invalid, `RESOURCE_EXHAUSTED / QUOTA_EXCEEDED` past 50 | `policy.proto` `Tag`, `mfa_device.proto` `TagMFADevice` |
| IAM tag value | 0-256 characters of the same alphabet, not beginning with `aws:` | `policy.proto` `Tag`, `mfa_device.proto` `TagMFADevice` |
| Password | 8-128 characters. Stored only as an argon2id hash. Never in operation records or logs | `user.proto` |
| `OUTPUT_ONLY` fields | Ignored on input by the AIP-203 convention. The comments in this repo do not state the server behaviour (needs checking). `status` is written only by servers and nodes | `google.api.field_behavior` |
| `request_id` | The same id with the same fingerprint returns the original operation; a different fingerprint is `ABORTED / IDEMPOTENCY_CONFLICT`. Remembered for 24 hours | `vws/common/v1/operation.proto` |
| `LookupOperation` `request_id` and `parent` | `request_id` is a UUID4 and required; `parent` is `projects/{project}`. Unset or malformed is `INVALID_ARGUMENT / INVALID_SPEC`. A `parent` other than the caller's project, or a `request_id` older than 24 hours, is `NOT_FOUND`, never `PERMISSION_DENIED` | `vws/compute/v1/operation_lookup.proto` |
| `generation` in status reports | A report lower than the stored value is ignored | `ObservedState` |
| `etag` | When set, it must equal the stored etag; otherwise `ETAG_MISMATCH` | `operation.proto` |

## Malicious and boundary input test baseline

The minimum inputs server repos put in their tests:

- Ids of length 0, 63 and 64. Ids with upper case, underscores, or leading or trailing hyphens.
- Objects whose key is `.`, `..`, the empty string, 1025 bytes, `a//b`, `/a`, or has control characters.
- A label with a 64-byte value, a label with a 64-character key.
- Annotations with a 128-character key and a 256-character value of multibyte characters (for example `é` or `漢`), which must be accepted because lengths are counted in Unicode characters, not bytes.
- Annotations with a 129-character key, a 257-character value, an empty key, a control character, and 51 user entries. The control-character case returns the `InvalidParameterValue` sentence above.
- A user create with an `aws:` key must be rejected, and 50 user entries plus server-set `aws:` entries must be accepted.
- An annotations UpdateMask write that omits a server-set `aws:` key leaves the key and its value in place, and one that sends that key with its stored value is accepted.
- Create and update requests with an `OUTPUT_ONLY` field (for example `claim_name`) filled in.
- A status report with a lower `generation`, an update with a wrong `etag`, a different body for the same `request_id`.
- IAM: a 65-character name, duplicate names differing only in case, an invalid JSON policy, an unsupported condition operator, a third access key, reuse of the same TOTP code, an expired session token and temporary key, a resync with a 129-character user name, an 8- or 257-character serial, a five-digit or non-digit code, and a reused pair, a permissions boundary ARN of 19 or 2049 characters, a user ARN as the boundary, another project's policy ARN, an empty or 10241-character encoded authorization message, a tampered one, one from another project, a 15- or 129-character access key id or one with `-`, a deleted or inactive access key, a federation `name` of 1 or 33 characters or with a space, a `duration_seconds` of 899 or 129601, 3601 for root (capped to 3600), a 2049-character or `\u0100` session policy, 11 `policy_arns`, another project's policy ARN, a GetFederationToken call with a console session or temporary key, an `Authorize` call for a federated principal with an empty or tampered `session_context`, a 19- or 2049-character `role_arn` or `principal_arn`, a 3- or 100001-character `saml_assertion`, a response that is not base64, unsigned, signed by another certificate, with two assertions, for another audience or issuer, or without a Role attribute, an expired assertion, a non-Success status, a Role attribute for another role, a `duration_seconds` of 899, 43201 or above the role's maximum, a replayed unexpired response (new credentials, nothing stored), a 1- or 65-character `role_session_name` or one with a space, a 3- or 20001-character `web_identity_token`, a token that is not three base64url parts, signed with `none` or HS256, with a tampered payload, from an issuer with no OIDC provider, for an audience not in the client id list, with a string `exp` or a future `nbf`, an expired token, a non-empty `provider_id`, an unreachable JWKS endpoint, a trust policy without `sts:AssumeRoleWithWebIdentity`, and a replayed unexpired token (new credentials, nothing stored).
- Snapshot permission: a `ModifyCreateVolumePermission` with no entries, 501 entries, `projects/A` (upper case), `projects/`, a bare project id, different projects in `add` and `remove`, `all` in both, and a call from a project the snapshot is shared with (must be `NOT_FOUND`, permission unchanged). A re-run of the same add, and an add of the owning project, leaves the permission unchanged.

## Schema change rules

- Field numbers are never reused. Removing or changing one fails `buf breaking` (FILE), and CI blocks it on the PR. Only when needed, write the narrowest exception in the PR body with its reason.
- A PR that changes proto states in its body whether it is breaking and its downstream impact (PR template).
